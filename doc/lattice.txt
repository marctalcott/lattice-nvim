1. INTRODUCTION                                                 *lattice-intro*

Lattice lists the tasks in your Markdown notes: what you owe (items that
start with an org-mode style keyword such as TODO) and what others owe you
(bullets under `Waiting On` headings). The
notes stay the only source of truth. Scanning is read-only, and nothing
leaves your machine.

Tested on Neovim 0.12.4 (macOS).

==============================================================================
2. SETUP                                                        *lattice-setup*

lazy.nvim / LazyVim (`~/.config/nvim/lua/plugins/lattice.lua`): >lua
    return {
      {
        "marctalcott/lattice-nvim",
        lazy = false,
        opts = { root = "~/Documents/WorkNotes" },
      },
    }
<
Without a plugin manager: >lua
    require("lattice").setup({ root = "~/Documents/WorkNotes" })
<
                                                              *lattice.setup()*
setup({opts})
    {root}     (string, required) Notes root. Lattice never guesses it.
    {keymaps}  (table|false) Keys for `open`, `refresh`, `add_todo`,
               `add_waiting`, `next_state`, `prev_state`. Each may be a
               key string or false. Set `keymaps = false` to create none.
               Defaults: `<leader>ll`, `<leader>lr`, `<leader>lt`,
               `<leader>ld`, `<leader>ln`, `<leader>lp`.

3. NOTE FORMAT                                                 *lattice-format*

Org-mode semantics, Markdown syntax. The full contract is
specs/LATTICE_SYNTAX_SPEC.md in the repository.
>markdown
    # Etna :engineering:

    ## IN PROGRESS [#A] Review system architecture :design:
    DEADLINE: <2026-11-05 Thu>
    :PROPERTIES:
    :ID: etna-review-001
    :END:
    - [x] Collect requirements
    - [ ] Draft the proposal
      SCHEDULED: <2026-11-03 Tue>
<
                                                              *lattice-tasks*
Tasks are:
- headings (`#` to `######`) whose text starts with a state;
- every checkbox item: `- [ ]`, `* [x]`, `+ [X]`, `1. [ ]`;
- bullets that start with a state, `- TODO x` (Lattice v0.1 form).
States match exactly. A state with no title, an empty checkbox, prose,
code blocks and front matter are never tasks. Headings and checkboxes form
one tree. Notes are read with Neovim's Tree-sitter Markdown parser.

                                                          *lattice-workflows*
Workflows list active, then done states. Default: TODO NEXT WAITING, then
DONE CANCELED. Set more under `workflows` in .lattice.json. A task's
workflow is its inherited `:WORKFLOW:` property, else its project's, else
the note's front matter `todo:` (v0.1), else `default`. States may contain
spaces. A task's project is an inherited `:PROJECT:`, front matter
`project:`, or the top-level `#` heading when it names a configured
workflow; most notes have none.

A checkbox's state is its `:STATE:` property, else the workflow's first
active state (`[ ]`) or first done state (`[x]`). The box decides whether
it is finished; a box that disagrees with its state is a warning.

                                                           *lattice-metadata*
Metadata goes directly below the title (inside the list item for a
checkbox):
- `SCHEDULED: <2026-11-05 Thu>`, `DEADLINE: <2026-11-09 Mon -3d>`,
  `CLOSED: [2026-11-09 Mon 14:30]`, with repeaters `+1w`, `++1m`, `.+1d`.
  Repeaters follow Org: `+` one interval from the date, `++` until the
  date is in the future, `.+` from the completion date. Months overflow
  like Org (Jan 31 +1m is Mar 3).
- Priority: `## TODO [#A] Title`, or `:PRIORITY: A` on a checkbox.
- Tags: `## TODO Title :a:b:`, or `:TAGS: a b` on a checkbox. Tags inherit
  from enclosing headings (`inherit.tags`).
- `:PROPERTIES:` drawers with any names; `:ASSIGNED:` is the person shown.
Problems (bad timestamps or weekdays, malformed drawers, unknown states,
priorities or workflows, duplicate IDs) are warnings; nothing is rewritten.

                                                            *lattice-waiting*
Lattice v0.1 syntax still reads: bullets under a `Waiting On` heading are
waiting items, a leading `@Name` is the assignee, `[due:YYYY-MM-DD]` is
the date (a DEADLINE wins), `[promised:YYYY-MM-DD]` is shown. Invalid
dates are listed under WARNINGS. |:LatticeHealth| counts v0.1 forms.

4. DASHBOARD                                                *lattice-dashboard*

Groups: MY TO DO, WAITING ON, OVERDUE (deadline before today, oldest
first), TODAY (scheduled today or earlier and still open, deadlines today),
DUE SOON (deadline inside its warning period: its own -Nd, else
`deadlines.warning_days`, default 14), and DONE (finished
tasks, the 20 most recent). Rows show state, priority, assignee and tags. INBOX appears when the
inbox folder exists. Owner groups list dated tasks first, by date, then
undated tasks by file and line.

    <CR>    Open the task's note at its line. Unsaved changes in an
            already-open buffer are kept.
    r       Rescan notes and reread .lattice.json
    q       Close and return to the previous buffer
    ?       Toggle help

Lattice reads saved files. Save a note, then refresh.

5. ADDING TASKS                                                *lattice-insert*

|:LatticeAddTodo| asks for text and adds `- TODO <text>` on the line below
the cursor, using the note's first open keyword (front matter, else root).
On a list item it matches the item's indent and goes after its
sub-bullets. Inside a Waiting On section the item counts as waiting. |:LatticeAddWaiting| asks for
an optional one-word name, then text, and adds `- [ ] @Name <text>` under
`Waiting On`:

- The Waiting On item goes after the section's last non-blank line.
- With several matching sections: the one containing the cursor, else the
  nearest one above the cursor, else the first.
- With none: Lattice asks before adding `## Waiting On` at the end.
- Cancelling any prompt leaves the buffer unchanged. The buffer is never
  saved for you.
- If an item lands inside a code block, Lattice warns that it can't list it.

                                                               *lattice-cycle*
|:LatticeNextState| and |:LatticePrevState| step the item under the cursor
through its keyword sequence, like org's S-Right and S-Left. With
`TODO NEXT | DONE CANCELED` the forward cycle is: no keyword, TODO, NEXT,
DONE, CANCELED, no keyword.

- Works on bullets (`-`, `*`, `+`, with or without a checkbox) and `#`
  headings. The keyword goes after the marker and checkbox; the checkbox is
  left alone.
- Uses the note's sequences (front matter, else root). An item stays in the
  sequence that holds its keyword; one without a keyword starts on the
  first sequence.
- Plain lines, numbered items, empty bullets, front matter and code blocks
  are refused with a message, and nothing changes.
- One undo step. The buffer is not saved.

6. COMMANDS AND KEYMAPS                                      *lattice-commands*

                                                                    *:Lattice*
:Lattice            Open or focus the dashboard.          (<leader>ll)
                                                             *:LatticeRefresh*
:LatticeRefresh     Rescan notes and .lattice.json.       (<leader>lr)
                                                             *:LatticeAddTodo*
:LatticeAddTodo     Add a TODO item below the cursor.     (<leader>lt)
                                                          *:LatticeAddWaiting*
:LatticeAddWaiting  Add a Waiting On item.                (<leader>ld)
                                                           *:LatticeNextState*
:LatticeNextState   Next state of the item under cursor.  (<leader>ln)
                                                           *:LatticePrevState*
:LatticePrevState   Previous state of the item.           (<leader>lp)
                                                              *:LatticeHealth*
:LatticeHealth      Same as `:checkhealth lattice`.

If a default key already has a global mapping, Lattice keeps your mapping,
warns once, and lists the key in |:LatticeHealth|. Running setup() again
removes the keys the previous run created. Invalid keymap values are
reported and ignored.

7. CONFIGURATION                                               *lattice-config*

Optional `.lattice.json` in the notes root: >json
    {
      "version": 1,
      "workflows": {
        "default": { "active": ["TODO", "NEXT", "WAITING"],
                     "done": ["DONE", "CANCELED"] },
        "etna": { "active": ["BACKLOG", "IN PROGRESS"], "done": ["COMPLETE"] }
      },
      "priorities": { "values": ["A", "B", "C"], "default": "B" },
      "inherit": { "tags": true, "properties": [] },
      "deadlines": { "warning_days": 14 },
      "scan": {
        "include": ["**/*.md"],
        "exclude": ["Archives/**", ".git/**"]
      },
      "headings": { "waiting": "Waiting On" },
      "inbox": { "path": "Inbox" }
    }
<
`todo` (Org sequences such as "TODO | DONE") still sets the default
workflow, as in v0.1; use it or `workflows.default`, not both.

Globs match whole paths relative to the root. `*` stays within one segment,
`**` spans any number of segments, and matching is case-sensitive. A
`scan.exclude` list replaces the default. `.git` directories and symbolic
links are always skipped. Changes apply on refresh. An invalid file shows an
error and scans nothing.

8. LIMITATIONS AND TROUBLESHOOTING                             *lattice-health*

- No file watching. Refresh by hand.
- Org subset in progress: completing tasks (advancing repeaters, CLOSED),
  editing that keeps checkboxes and :STATE: in sync, and progress cookies
  come in later milestones. |lattice-cycle| edits the state word only.
- A broken Tree-sitter parser binary can crash Neovim; delete it and run
  :TSUpdate.
- WBR, AI discovery, Portico publishing and Drafts import are not built.

|:LatticeHealth| shows the root, config status, the Markdown parser,
counts, unreadable paths, invalid dates and note warnings with file and
line, workflows, v0.1 syntax in use, and skipped keymaps.
