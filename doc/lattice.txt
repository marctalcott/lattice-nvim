1. INTRODUCTION                                                 *lattice-intro*

Lattice lists the tasks in your Markdown notes: what you owe (items that
start with an org-mode style keyword such as TODO) and what others owe you
(bullets under `Waiting On` headings). The
notes stay the only source of truth. Scanning is read-only, and nothing
leaves your machine.

Tested on Neovim 0.12.4 (macOS).

==============================================================================
2. SETUP                                                        *lattice-setup*

lazy.nvim / LazyVim (`~/.config/nvim/lua/plugins/lattice.lua`): >lua
    return {
      {
        "marctalcott/lattice-nvim",
        lazy = false,
        opts = { root = "~/Documents/WorkNotes" },
      },
    }
<
Without a plugin manager: >lua
    require("lattice").setup({ root = "~/Documents/WorkNotes" })
<
                                                              *lattice.setup()*
setup({opts})
    {root}     (string, required) Notes root. Lattice never guesses it.
    {keymaps}  (table|false) Keys for `open`, `refresh`, `add_todo`,
               `add_waiting`, `next_state`, `prev_state`, `set_state`,
               `toggle_checkbox`, `schedule`, `deadline`, `priority_up`,
               `priority_down`, `refile`, `archive`. Each may be a key
               string or false. Set
               `keymaps = false` to create none. Defaults: `<leader>ll`,
               `<leader>lr`, `<leader>lt`, `<leader>ld`, `<leader>ln`,
               `<leader>lp`, `<leader>ls`, `<leader>lx`, `<leader>lS`,
               `<leader>lD`, `<leader>l+`, `<leader>l-`, `<leader>lw`,
               `<leader>lA`.

3. NOTE FORMAT                                                 *lattice-format*

Org-mode semantics, Markdown syntax. The full contract is
specs/LATTICE_SYNTAX_SPEC.md in the repository (see its Amendment 1).
>markdown
    # Etna :engineering:

    ## IN PROGRESS [#A] Review system architecture [1/2] :design:
    DEADLINE: <2026-11-05 Thu>
    :PROPERTIES:
    :ID: etna-review-001
    :END:
    - [x] Collect requirements
    - [ ] Draft the proposal
<
                                                              *lattice-tasks*
As in Org-mode, tasks are headings (`#` to `######`) whose text starts with
a state. Checkboxes (`[ ]`, `[x]`, `[X]`, Org's partly done `[-]`) are
steps: a heading's progress counts the top-level checkboxes directly in
its entry, else its child TODO headings. They are not listed on the
dashboard. States match exactly. Prose, code blocks and front matter are
never tasks. Notes are read with Neovim's Tree-sitter Markdown parser.

                                                          *lattice-workflows*
Workflows list active, then done states. Default: TODO NEXT WAITING, then
DONE CANCELED. Set more under `workflows` in .lattice.json. A task's
workflow is its inherited `:WORKFLOW:` property, else its project's, else
the note's front matter `todo:` (v0.1), else `default`. States may contain
spaces. A task's project is an inherited `:PROJECT:`, front matter
`project:`, or the top-level `#` heading when it names a configured
workflow; most notes have none.

                                                           *lattice-metadata*
Metadata belongs to headings and goes directly below them (blank lines
in between, as Markdown formatters add, are allowed):
- `SCHEDULED: <2026-11-05 Thu>`, `DEADLINE: <2026-11-09 Mon -3d>`,
  `CLOSED: [2026-11-09 Mon 14:30]`, with repeaters `+1w`, `++1m`, `.+1d`.
  Repeaters follow Org: `+` one interval from the date, `++` until the
  date is in the future, `.+` from the completion date. Months overflow
  like Org (Jan 31 +1m is Mar 3).
- Priority: `## TODO [#A] Title` (a :PRIORITY: property sets nothing).
- Tags: `## TODO Title :a:b:`. Tags inherit from enclosing headings
  (`inherit.tags`).
- `:PROPERTIES:` drawers with any names; `:ASSIGNED:` is the person shown.
Problems (bad timestamps or weekdays, malformed drawers, unknown states,
priorities or workflows, duplicate IDs) are warnings; nothing is rewritten.

                                                            *lattice-waiting*
Lattice v0.1 syntax still reads: bullets with a state (`- TODO x`) are
items in that state, bullets under a `Waiting On` heading are waiting items, a leading `@Name` is the assignee, `[due:YYYY-MM-DD]` is
the date (a DEADLINE wins), `[promised:YYYY-MM-DD]` is shown. Invalid
dates are listed under WARNINGS. |:LatticeHealth| counts v0.1 forms.

4. DASHBOARD                                                *lattice-dashboard*

Groups: MY TO DO, WAITING ON, OVERDUE (deadline before today, oldest
first), TODAY (scheduled today or earlier and still open, deadlines today),
DUE SOON (deadline inside its warning period: its own -Nd, else
`deadlines.warning_days`, default 14), and DONE (finished
tasks, the 20 most recent). Rows show state, priority, assignee and tags. INBOX appears when the
inbox folder exists. Owner groups list dated tasks first, by date, then
undated tasks by file and line.

    <CR>    Open the task's note at its line. Unsaved changes in an
            already-open buffer are kept.
    r       Rescan notes and reread .lattice.json
    q       Close and return to the previous buffer
    ?       Toggle help

Lattice reads saved files. Save a note, then refresh.

                                                          *lattice-views*
Views: `1` overview, `2` week agenda (Org's C-c a a: each day's scheduled
items, deadlines and repeats; today adds `Sched. Nx`, `N d. ago` and
`In N d.`; `b` / `f` / `.` move between weeks), `3` all TODOs by priority
(C-c a t), `4` projects (counts, status, next action; <CR> lists one
project's TODOs).

`F` filters every view (`/` still searches). Quote values with spaces,
`project:"Home Renovation"`: `+tag` `-tag` `#A` `project:Name` `@person`
`state:NEXT` and title words. An empty answer clears it.

Editing rows, as in Org's agenda: `t` state, `+` / `-` priority, `S` / `D`
SCHEDULED / DEADLINE. Edits go to the note's buffer (opened in the
background if needed), unsaved; `s` saves the notes edited from here.

Lattice re-parses only notes that changed, reads unsaved open buffers,
and refreshes an open dashboard when a note under the root is saved.

5. ADDING TASKS                                                *lattice-insert*

|:LatticeAddTodo| asks for text and adds `## TODO <text>`, like Org's
C-S-RET: at the level of the heading the cursor is in, after its subtree
(a level-2 heading below the cursor when there is none). The state is the
first active state of the workflow in effect there.

|:LatticeAddWaiting| asks for an optional person, then text, and adds
`## WAITING <text>` the same way, with `:ASSIGNED: <person>` in a drawer.
It adds nothing if that workflow has no WAITING state.

Blank lines go around the new heading. Cancelling a prompt changes
nothing. The buffer is never saved for you. If the heading lands inside a
code block, Lattice warns that it can't list it.

                                                               *lattice-cycle*
|:LatticeNextState| and |:LatticePrevState| step the heading under the
cursor through its workflow, like org's S-Right and S-Left. With
`TODO NEXT | DONE CANCELED` the forward cycle is: no keyword, TODO, NEXT,
DONE, CANCELED, no keyword.

- Works on `#` headings; priority, tags and closing #s are kept.
- Uses the workflow in effect on that line. A heading stays in the
  sequence that holds its state; one without a state starts on the first.
- List items aren't tasks in Org and never gain a state; a v0.1 keyword
  bullet can still change or drop its state.
- Plain lines, front matter and code blocks are refused with a message,
  and nothing changes.
- One undo step. The buffer is not saved.

                                                               *lattice-edit*
Editing commands follow Org and change only the current buffer, as one
undo step; nothing is saved. A stale or repeated command is refused.

:LatticeSetState      Choose a state (C-c C-t).               <leader>ls
:LatticeToggleCheckbox  Toggle a checkbox (C-c C-c).          <leader>lx
:LatticeSchedule      Set/remove SCHEDULED (C-c C-s).         <leader>lS
:LatticeDeadline      Set/remove DEADLINE (C-c C-d).          <leader>lD
:LatticePriorityUp / :LatticePriorityDown  (S-Up/S-Down).  <leader>l+ / l-
:LatticeMigrate       Convert this note's v0.1 items to Org headings.

- Completing adds `CLOSED: [...]` when `logging.done` is "time" (off by
  default). Reopening removes it.
- Completing a repeating task advances its SCHEDULED/DEADLINE, keeps it
  open in its previous state (or `repeat_to_state`), and with
  `logging.repeat` "time" (default) records :LAST_REPEAT: and a state note.
- `enforce.checkboxes` / `enforce.todo` block completion while steps or
  subtasks are open (off by default).
- Toggling a checkbox writes [x]; a parent's children follow it; parent
  boxes become [x] or [-] from their children, and [n/m] / [n%] cookies
  on parent items and the heading are recalculated.
- Dates: YYYY-MM-DD, today, tomorrow, +3d/+2w/+1m/+1y, optional HH:MM;
  empty removes. Repeaters and warnings are kept.
- Priority: none starts at the default; past either end removes it.

                                                             *lattice-refile*
:LatticeRefile   (<leader>lw, Org's C-c C-w) moves the subtree under the
cursor under a heading chosen from every note, re-levelled, or to the end
of a note.
:LatticeArchive  (<leader>lA) moves it to `archive.location` (default
"%s_archive.md" beside the note) as a top-level heading with Org's
ARCHIVE_TIME, ARCHIVE_FILE, ARCHIVE_OLPATH, ARCHIVE_CATEGORY and
ARCHIVE_TODO properties. Archive notes are excluded from scanning by
default. Both change buffers only; both notes are checked first.

                    o open, R fetch, q close.             (<leader>li)

If a default key already has a global mapping, Lattice keeps your mapping,
warns once, and lists the key in |:LatticeHealth|. Running setup() again
removes the keys the previous run created. Invalid keymap values are
reported and ignored.

7. CONFIGURATION                                               *lattice-config*

Optional `.lattice.json` in the notes root: >json
    {
      "version": 1,
      "workflows": {
        "default": { "active": ["TODO", "NEXT", "WAITING"],
                     "done": ["DONE", "CANCELED"] },
        "etna": { "active": ["BACKLOG", "IN PROGRESS"], "done": ["COMPLETE"] }
      },
      "priorities": { "values": ["A", "B", "C"], "default": "B" },
      "inherit": { "tags": true, "properties": [] },
      "deadlines": { "warning_days": 14 },
      "logging": { "done": false, "repeat": "time" },
      "enforce": { "checkboxes": false, "todo": false },
      "scan": {
        "include": ["**/*.md"],
        "exclude": ["Archives/**", ".git/**"]
      },
      "headings": { "waiting": "Waiting On" },
      "inbox": { "path": "Inbox" }
    }
<
`todo` (Org sequences such as "TODO | DONE") still sets the default
workflow, as in v0.1; use it or `workflows.default`, not both.

Globs match whole paths relative to the root. `*` stays within one segment,
`**` spans any number of segments, and matching is case-sensitive. A
`scan.exclude` list replaces the default. `.git` directories and symbolic
links are always skipped. Changes apply on refresh. An invalid file shows an
error and scans nothing.

8. LIMITATIONS AND TROUBLESHOOTING                             *lattice-health*

- Refresh on save or with `r`; files changed outside Neovim are picked
  up on the next refresh.
- Org subset: no clocking, tables, links, capture templates or export.
- A broken Tree-sitter parser binary can crash Neovim; delete it and run
  :TSUpdate.
- WBR, AI discovery, Portico publishing and Drafts import are not built.

|:LatticeHealth| shows the root, config status, the Markdown parser,
counts, unreadable paths, invalid dates and note warnings with file and
line, workflows, v0.1 syntax in use, and skipped keymaps.
